Your **205 pytest tests** are:

- **6 Advanced Edge Case Tests** (MOCKED)  
- **7 Integration Tests** (OPTIONAL - real API calls)

## Detailed Breakdown

### 1. UNIT TESTS (199 tests) - What You Have

**Location:** `tests/test_*.py` files  
**Run command:** `pytest tests -m "not integration"`  
**Time:** ~9 seconds  
**Cost:** $0

**What they test:**
```python
# Example Unit Test
def test_extract_json():
    text = '[{"id": "TC_1"}]'
    result = extract_json(text)
    assert result == [{"id": "TC_1"}]
```

**Key characteristics:**
- ✅ Test ONE function at a time
- ✅ Use MOCKS to prevent real API calls
- ✅ Don't require internet connection
- ✅ Run in milliseconds
- ✅ Test logic, not UI
- ✅ Examples:
  - Can extract_json parse this string?
  - Does normalize_tc format steps correctly?
  - Does style_sheet apply colors properly?

**Files:**
- `test_helpers.py` - utility functions
- `test_load_requirements.py` - file loading
- `test_stage_*.py` - individual pipeline stages
- `test_excel_reports.py` - output formatting
- `test_error_handling.py` - edge cases

---

### 2. INTEGRATION TESTS (7 tests, Optional)

**Location:** `tests/test_pipeline_integration.py`  
**Run command:** `pytest -m integration`  
**Time:** 2-5 minutes per run  
**Cost:** $1-2 per run  
**Status:** ⚠️ OPTIONAL - requires real API key

**What they test:**
```python
# Example Integration Test
def test_full_pipeline_end_to_end():
    # REAL API CALL - costs money
    result = run_pipeline(
        requirements="User login requirements...",
        testcases_per_day=20,
        output_dir="/tmp/test_output"
    )
    
    assert len(result['test_cases']) > 0
    assert result['automation_summary']['total'] > 0
    assert len(result['files']) == 6  # All reports generated
```

**Key characteristics:**
- ✅ Test the ENTIRE pipeline (all 6 stages)
- ✅ Use REAL OpenAI API (costs $)
- ✅ Verify data flows from start to finish
- ✅ Slower but more realistic
- ✅ Test pipeline logic but NOT the UI
- ✅ Examples:
  - Do requirements really get analyzed?
  - Are test cases actually generated?
  - Do Excel files work with real data?

**Coverage:**
- Requirements → Test Cases → Reviews → Fixes → Automation Assessment → Estimation
- All 6 pipeline stages tested together
- Validates JSON parsing with real LLM output

### 3. END-TO-END (E2E) TESTS (Generated by TestSprite)

**Status:** ❌ NOT in pytest suite - TestSprite generates these  
**Run command:** Manual via Copilot Chat + TestSprite MCP  
**Time:** 2-5 minutes per run  
**Cost:** $0 (ngrok + TestSprite API are free tier)

**What they test:**
```
User opens browser
  ↓
Navigates to https://your-app.ngrok-free.app
  ↓
Clicks "Upload File" button
  ↓
Selects requirements file
  ↓
Clicks "Generate"
  ↓
Waits for progress bar
  ↓
Downloads Excel file
  ↓
Verifies file is valid Excel
```

**Key characteristics:**
- ✅ Test via WEB BROWSER (real UI)
- ✅ Automate actual user clicks/inputs
- ✅ Test Streamlit UI rendering
- ✅ Test file downloads/uploads
- ✅ Take screenshots of each step
- ✅ Test actual user experience
- ✅ Examples:
  - Can user see the app?
  - Does file upload work?
  - Do progress indicators show?
  - Can user download results?

**TestSprite generates:**
- Automated browser interactions
- Screenshots of each step
- Pass/fail results
- HTML/JSON reports
- Evidence of what happened

## Which Tests to Run When

### Daily Development
```powershell
# Run fast unit tests (9 seconds)
pytest tests -m "not integration" -q
```
✅ Gets instant feedback on code changes

### Before Committing
```powershell
# Run all unit tests
pytest tests -m "not integration" -v
```
✅ Ensures nothing broke

### Before Release
```powershell
# Run everything
pytest tests -v                    # All unit tests
pytest -m integration -v           # Integration tests ($1-2)
# Then manually run TestSprite     # E2E tests
```
✅ Full validation before release

### When Testing UI Changes
```powershell
# TestSprite E2E tests ONLY
# (Not pytest - use Copilot Chat method from GENERATE_TESTSPRITE_PLAN.md)
```
✅ Verifies UI looks/works correctly
